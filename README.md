# GREEN-API Chat

**Демо:** https://greenapi-tz-mu.vercel.app/


Веб-клиент для отправки и получения текстовых сообщений через [GREEN-API](https://green-api.com).
Интерфейс повторяет Telegram Web: список чатов, пузыри сообщений, статусы прочтения, светлая и тёмная тема.

Тестовое задание на позицию «Фронтенд-разработчик React». Сделано для Telegram: в задании это разрешено
как замена MAX, а методы GREEN-API для обоих мессенджеров одинаковые.

**Стек:** React 19, TypeScript, Vite, Tailwind CSS v4, Vitest. Бэкенд не нужен: браузер обращается к GREEN-API напрямую.

## Подготовка инстанса

1. Создайте инстанс в [консоли GREEN-API](https://console.green-api.com) и авторизуйте его аккаунтом мессенджера.
   Лучше взять аккаунт без подписок на каналы: посты каналов тоже попадают в очередь уведомлений.
2. В настройках инстанса:
   - оставьте **URL вебхука пустым**, иначе уведомления уйдут на вебхук и не попадут в очередь HTTP API;
   - включите **входящие сообщения** (`incomingWebhook`);
   - по желанию включите **статусы исходящих** (`outgoingWebhook`) — для галочек «прочитано»;
   - по желанию включите **сообщения, отправленные с телефона** (`outgoingMessageWebhook`) — чтобы они тоже появлялись в чате.
3. На экране входа введите `idInstance` и `apiTokenInstance`. `apiUrl` подставляется по первым четырём цифрам `idInstance`,
   при необходимости его можно исправить.

## Сценарий

1. Вход по `idInstance` и `apiTokenInstance`. Данные проверяются методом `getStateInstance`.
2. Карандаш → номер телефона получателя → новый чат.
3. Сообщение отправляется методом [`sendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/).
4. Получатель отвечает в мессенджере.
5. Ответ приходит через [HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/)
   (`receiveNotification` + `deleteNotification`) и появляется в чате.

## Как это устроено

### Приём сообщений

[`useNotificationPolling`](src/hooks/useNotificationPolling.ts) в цикле вызывает `receiveNotification` с `receiveTimeout=20`.
Это long polling: сервер держит запрос, пока не придёт уведомление, поэтому ответ появляется почти сразу.

- Запросы идут строго последовательно (`while` + `await`, а не `setInterval`), поэтому уведомления не обрабатываются дважды.
- Каждое уведомление удаляется через `deleteNotification`, даже ненужное, иначе очередь встанет на нём.
- Цикл останавливается через `AbortController` при выходе и размонтировании. Это же защищает от двойного эффекта в StrictMode.
- У запросов есть таймауты. При ошибке сети цикл переподключается через 3 секунды и показывает «Ожидание сети…».
- При ответе 401/403 (токен отозван) пользователь возвращается на экран входа с пояснением.

**Почему не WebSocket.** У GREEN-API нет WebSocket для получения уведомлений: есть HTTP API (long polling) и вебхуки,
для которых нужен собственный сервер. Задание требует именно HTTP API, а long polling и так даёт задержку около секунды.

### Разбор уведомлений

[`parseNotification`](src/lib/notifications.ts) превращает уведомление в событие приложения:

| `typeWebhook`             | Что делаем                                                 |
| ------------------------- | ---------------------------------------------------------- |
| `incomingMessageReceived` | входящее сообщение                                         |
| `outgoingMessageReceived` | сообщение, отправленное с телефона                         |
| `outgoingMessageStatus`   | статус: `delivered` → ✓, `read` → ✓✓, `noAccount` → ошибка |
| всё остальное             | удаляем из очереди без обработки                           |

Показываются только текстовые сообщения (`textMessage`, `extendedTextMessage`) из личных чатов (`chatType: "user"`).
Каналы, группы и медиа пропускаются.

### Сопоставление ответа с чатом

Мы отправляем на `77470467897@c.us`, а в уведомлении Telegram `chatId` приходит числовым id (`"5881406513"`).
Поэтому [`chatReducer`](src/store/chatReducer.ts) ищет чат по номеру из `senderPhoneNumber` и запоминает числовой id
как `remoteId`. Если номер скрыт (`senderPhoneNumber: 0`), создаётся чат по `chatId`, и ответы уходят на него.
Повторные уведомления отбрасываются по `idMessage`.

### Несколько вкладок

Очередь уведомлений у инстанса одна. Если её читают две вкладки, каждая получит только часть сообщений.
[`useTabLock`](src/hooks/useTabLock.ts) через Web Locks API разрешает опрос только одной вкладке.
Вторая показывает «Чат открыт в другой вкладке» с кнопкой «Открыть здесь», как Telegram Web.

### Отправка

Сообщение сразу появляется в ленте со статусом «отправляется» (оптимистичное обновление).
После ответа `sendMessage` временный id заменяется настоящим `idMessage`. При ошибке рядом с сообщением появляется «!»,
по клику сообщение отправляется заново.

## Структура

```
src/
  api/greenApi.ts                 методы GREEN-API, таймауты, ошибки

  lib/phone.ts, format.ts         номера телефонов, даты
  lib/storage.ts                  localStorage
  store/                          состояние чатов (useReducer + Context)
  components/                     интерфейс
```

## Ограничения

- История хранится только в `localStorage` этого браузера (до 500 последних сообщений на чат).
  Загрузку старой истории с сервера задание не требует.
- `apiTokenInstance` хранится в `localStorage`, чтобы не вводить его после перезагрузки.
  Для учебного клиента без бэкенда это допустимо, но в продакшене токен стоит держать на сервере.
